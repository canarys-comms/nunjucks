Questions teams usually ask

Frequently asked questions about Atlassian Forge

Key questions when adopting Atlassian Forge in an enterprise environment.

Where does Atlassian Forge fit in an enterprise architecture?

Atlassian Forge should own a clear responsibility around Forge functions, UI extensions, storage, product APIs, permissions and app lifecycle. A useful placement is one where it directly supports custom Jira workflow experiences or issue actions and the integration boundaries are explicit.

What should be standardized when adopting Atlassian Forge?

Standardize the repeatable parts first: permission scopes and environment separation, plus reusable patterns from Forge app design and Jira and Confluence extensions. Leave workload-specific choices closer to the teams that own them.

What problems commonly appear when Atlassian Forge scales?

Common signals include legacy customizations are copied into cloud without redesign, apps request broad scopes, and UI logic and backend functions become tightly coupled. These usually indicate that Atlassian Forge adoption has outgrown the original team-level operating model.

How does Canarys help with Atlassian Forge?

Canarys supports Forge app design, Jira and Confluence extensions, custom UI and UI Kit, and product API integration, then connects the result to enterprise governance and operations so Atlassian Forge can be maintained as a capability rather than a one-off implementation.
